# 架构与部署

## 部署边界

每位成员安装桌面 App，继续使用自己的 Codex 或 DSH。所有客户端和插件连接同一个 Go 服务。服务连接 PostgreSQL，负责认证、授权、事务、版本及永久记录。Tauri Rust 层仅处理必要的本机功能与系统凭证库，不在每台电脑各建一份公司共享数据库。

本机开发由专用 Docker PostgreSQL + 本机 Go + Tauri 组成。公司部署时，在服务器部署同一 Go 程序及 PostgreSQL，配置客户端连接地址；HTTPS 可由公司现有反向代理终止。业务数据库不暴露到公网。API 服务本身不保存供应商模型密钥、不统一代理成员全部模型调用。

## 单仓库布局

```
apps/desktop/            React + shadcn/ui 桌面界面与 src-tauri Rust 本机层
services/server/         Go 模块化单体、PostgreSQL 存储、集成测试
plugins/mcp-bridge/      通用 MCP stdio 接入与工具策略
plugins/codex/           Codex 插件清单、技能及打包运行时
plugins/deepseek-harness/ Cordis 接入及显式会话绑定
scripts/                本机环境、启动、演示、验证
docs/                  规则、API 契约与验证记录
```

不预先引入微服务、Redis、Kafka 或独立向量数据库。共享记忆首先是结构化的事实和版本，语义检索可以在确有需求时补充。

## 记忆和责任

已发布记忆构成任务依据；任务记录 memoryRefs，执行方显式同步，提交与验收核对变化。发布和提交在同一项目的事务边界内检查，防止检查完毕后被并发发布绕过。草稿、旧版及讨论不自动进入正式依据。项目复制后独立演进，继承内容先成为草稿，保留来源。

移交替换当前职责、未完成任务及待办问题，历史作者与完成成果留存。接手确认独立记录。离职停用撤销访问，仍有职责时先完成转派。后续供应商账号、外部系统权限和凭证回收仍需管理员按对应系统执行。

## 通信和授权

公开工作频道按项目权限读取，私聊和小群仅参与者读取，包括管理员本人也不能例外。读取与任务接单分开记录。聊天提炼先生成草稿，正式发布仍走原有记忆权限。私聊不自动送入共享 AI 上下文。

首版采用在线轮询读取持久消息，界面展示同步状态；恢复连接后重新查询历史及未读。没有将客户端在线状态解释成已送达或已读。消息不提供修改/删除；附件、消息留存策略及更完整的审计导出后续扩展。

## 用量

记录模型适配器真实返回的数据；缺失就保持未知，不能把估算伪装为账单。inputTokens 已包含 cacheReadTokens，汇总不再加一次缓存读取。账单金额与估算金额按币种分开。请求重试可能实际产生新费用，事件重放则应使用同一个 requestId 去重。

用户可自己使用不同供应商，不要求请求统一经过平台。但这也意味着平台只能统计已接入并上报的调用，无法据此证明公司账号全部消费。平台不提供跨供应商的统一“剩余 token”。

## 凭证与备份

Go 服务使用环境变量读取数据库地址和 bootstrap 管理员 token，数据库只保存成员访问 token 的哈希。客户端系统凭证库存成员平台 token；浏览器开发状态仅保存在当前会话，不应作为正式部署方式。源代码与 Git 仓库不包含 `.env`、数据库数据卷或真实成员 token。

PostgreSQL 是唯一持久事实来源。正式试点前应配置定期备份并演练恢复；本地 `docker stop intelligent-organization-postgres` 保留卷，不能把删除数据卷当成日常停止方式。
